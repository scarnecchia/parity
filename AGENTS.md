# Sentinel parity

Last verified: 2026-09-28

## Stack and commands

- Python >=3.12.13; Typer, polars-readstat, Polars, PyArrow, DuckDB, Jinja2, XlsxWriter; setuptools/pip packaging.
- Create the environment with `python3 -m venv .venv`; install with `TMPDIR="$PWD/.tmp" .venv/bin/python -m pip install -e '.[dev]'` (this host's `/tmp` is a full tmpfs).
- Run `python -m pytest`, `python -m ruff check .`, `python -m ruff format --check .`, `python -m mypy src`, and `python -m build` inside `.venv`.
- Real external test inputs are explicitly downloaded with `python -m tests.acquire_fixtures`; tests never download. Cache stays in ignored `.parity-fixtures/` and must never enter wheel or sdist.

## Architecture and invariants

- `core/` contains pure normalization, typed value encoding, comparison SQL generation, export/presentation policy (`core/export_policy.py`), and report modeling. It does not import filesystem/database readers.
- `io/` and `runner.py` are imperative shells for TOML/filesystem access, polars-readstat/Arrow staging, DuckDB comparison, and report output. Keep each runtime source file classified by its `# pattern:` line. Staging encodes each batch with the vectorized builders in `core/vector_encoding.py` (byte-identical keys and envelope payloads to the scalar path, with exact scalar fallbacks: unsigned widths, Decimal, binary, floats under `round_digits`, JSON-escaped strings, infinite/huge floats) — never reintroduce per-cell Python encode loops. Detail JSONL is exported inside DuckDB (`json_object` + `COPY` with quoting disabled) and stays nondeterministically ordered. Comparison runs database-side over a narrow difference relation: differences are never fully materialized in Python, the runner never rereads the JSONL, and counts, previews, and byte sizes come back from the comparison before the connection closes. `--id` (`id`) places the report in `output_dir`/`<id>` — letters, numbers, and underscores only, at most 64 characters, `details` reserved — the effective report directory must be absent or empty, and `summary.json` records the id as `request_id`. Every run that creates the report directory writes structured JSONL events to `run.jsonl` (`io/run_log.py`; `--verbose` echoes them to stderr): counts, durations, paths, and OSError errno/strerror only — never cell values or raw exception text. When the run temp resolves onto tmpfs, a `temp_on_tmpfs` event plus a stderr hint recommend `--temp-dir` on real disk (no auto-diversion). Failed runs keep `run.jsonl`, so the directory stays non-empty until manually cleared — never delete the log to make a retry pass. `--threads` (default 4) sets DuckDB worker threads; the underscore flag aliases `--sas_root`/`--python_root` are gone in favor of `-s`/`-p`.
- Report artifacts are versioned. Detail JSONL v2 holds nested paired differences only — records `{schema_version: 2, dataset_id, pair_id, kind, sas_row, python_row, differences: [{column, sas, python}]}` with `kind` `paired_mismatch`, `only_sas`, or `only_python`; there are no full-row match records and no `absent_column` envelopes. A null top-level `sas_row`/`python_row` denotes the absent side, while a JSON-null cell inside `differences` is a present None value; the `differences` array (entries ordered by column name) is authoritative for which columns differ. `summary.json` is schema v3 with `details_schema_version: 2`, `difference_row_count` (flat difference rows across all exported records, not JSONL record count), `details_bytes`, per-dataset `preview_truncation` `{shown_rows, omitted_rows, rendered_bytes, reasons}`, per-dataset effective `pair_keys`, and an `excel` block `{status, path, reasons, limits, measurements}` (`status` is `disabled`/`omitted`/`generated`/`no_differences`; `reasons` entries are `{code, dataset_id}` — run-level codes carry a null dataset id and only `sheet_row_limit` names its dataset; `measurements` cover exactly the datasets staged while the workbook was still eligible). Report previews are clipped in SQL and byte-budgeted: `preview_rows` counts flat difference rows per dataset, bounded with `preview_max_bytes`/`preview_total_max_bytes`/`preview_cell_chars`. Preview and workbook cells mark missing values through one shared SQL predicate pinned to Python's `str.rstrip()` whitespace set — the comparison's exact missing rule — so both surfaces annotate them identically.
- SAS and Parquet rows are compared as exact, order-independent multisets. Canonical equality keys are per-column; never replace them with hash-only equality or delimiter concatenation.
- Comparison is value-only: declared column types are never a factor, and a type difference alone can never fail a dataset. Decoded values match iff equal in one value space — numbers by reduced rational value (16.0 = 16; 16.2 != 16) with numeric-looking text coerced to numbers; booleans as 1/0; temporals as exact instants (naive as UTC, dates as midnight); null, NaN, and blank or whitespace-only text as one missing value; other text exactly after trailing-whitespace trim (SAS blank padding). `--round N` (`round_digits`) rounds numeric values — including coerced numeric text — to N digits after the decimal point (nearest, ties away from zero) before comparison; omitted compares raw. Keep Int64 ordinals/counts and stream rows in bounded batches.
- Files are paired by identity before any input is opened; a file with no equivalent on the other side is never read — no staging, row count, reader metadata, or detail export — and is flagged at the top of the report as `missing_counterpart` with `null` counts on the side that exists.
- Excess rows are paired by ascending, null-safe canonical value order — declared `pair_keys` first when configured (TOML `pair_keys` / CLI `--pair-keys`; keys missing from a dataset's shared columns are logged as `pair_keys_unused` and dropped; the effective keys are recorded per dataset), then the remaining shared columns (`pair_id`); original staging ordinals remain visible. Pairs are diagnostics, not proof of correspondence, and never change pass/fail. The report states the pairing basis and outlines paired rows whose differences include a pairing key. Severity is always classified on the automatic pairing; when declared keys also pair rows outside the crossed columns, the `type_mismatch` condition carries a `pairing_note` saying its pass verdict is measured on the automatic pairing. Comparison always runs on the columns both sides share — a column-set delta never stops the row checks. Every compared dataset carries `conditions` (all problems found, not just the first): `sas_only_columns` FAILs (Parquet lacks columns SAS has), `python_only_columns` WARNs (extra Parquet values are not compared), and shared-value mismatches FAIL as `value_mismatch` or WARN as `type_mismatch` when every difference falls inside character-vs-numeric columns (listed in `type_mismatched_columns`). Status is FAIL if any condition fails, WARN if only warnings remain (exit 0), PASS if none; `reason` repeats the most severe condition code. The report leads each non-passing dataset with one plain-language sentence per condition and renders bounded flat difference-row previews (pair, column, both values, types, rows, kind) with visible truncation when budgets clip rows or cells; full values remain in the JSONL. Pairs are diagnostics, not proof of row correspondence. Report dataset sections are ordered by dataset name. Comparison is order-independent; `row_order_mismatches` counts matched rows whose file positions differ, and the report flags it at the top of the dataset section. WARN does not fail the run (exit 0).
- The Excel workbook is generated automatically; `excel=false`/`--no-excel` disables it. Budgets `excel_max_sheets`/`excel_max_rows`/`excel_max_rows_per_sheet`/`excel_max_bytes` are configurable positive integers, and hard Excel caps (1,048,575 data rows, 100 sheets including Index, 32,767 characters per cell) apply over configuration. The workbook is all-or-nothing: any exceeded budget omits it entirely with recorded reasons, per-dataset Parquet staging is written only while budgets remain eligible and released once a mid-run budget gate trips or the final pre-write check leaves the workbook ungenerated, and writing uses XlsxWriter constant memory with `write_string` for every source value — Int64 identifiers included as text — finalized before atomic publication.
- Reports may carry sensitive data; never place cell values in logs or console errors. Publish generated artifacts atomically, keep output/temp outside inputs, and clean owned temp data on failure/interruption.
